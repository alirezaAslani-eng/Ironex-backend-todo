## ۱۴. آپدیت نشدن کیف پول بعد از سفارش فروش

سفارش‌های فروش، هم در حالت **فوری** و هم در حالت **تعیین قیمت**، فقط باعث آپدیت لیست سفارش‌های کاربر و Order Book می‌شوند و کیف پول آپدیت نمی‌شود.

این مورد با لاگ‌های دقیق در Frontend تست و تأیید شده است.

---

## ۱۵. مشکل سفارش تعیین قیمت بر اساس قیمت واردشده

در سفارش‌های **تعیین قیمت**، رفتار سیستم بر اساس قیمت واردشده متفاوت است.

در سفارش خرید، اگر قیمت واردشده به نفع قیمت فعلی بازار باشد، کیف پول آپدیت می‌شود؛ اما اگر قیمت واردشده پایین‌تر از قیمت بازار باشد، فقط لیست سفارش‌ها و Order Book آپدیت می‌شوند و کیف پول تغییری نمی‌کند.

در سفارش فروش، به دلیل وجود باگ مستقل در آپدیت کیف پول فروش، حتی اگر قیمت واردشده به نفع بازار باشد، باز هم کیف پول آپدیت نمی‌شود و فقط لیست سفارش‌ها و Order Book آپدیت می‌شوند.

---

## ۱۶. مشکل سفارش‌های با حجم بالا

سفارش‌هایی با حجم بسیار بالا، مانند `100000000`، اصلاً وارد Order Book نمی‌شوند؛ حتی بعد از Refresh صفحه.

همچنین برای این سفارش‌ها:

- آپدیت Real-time کیف پول انجام نمی‌شود.
- بعد از Refresh مشخص می‌شود که کیف پول در واقع آپدیت شده است.
- سفارش در Order Book نمایش داده نمی‌شود.
- امکان لغو این سفارش‌ها وجود ندارد.

---

## ۱۷. ارسال نشدن Event مربوط به تغییر قیمت بازار

Event مربوط به `OnMarketPriceChanged` از سمت Backend ارسال نشد و امکان تست رفتار Frontend در زمان دریافت این Event وجود نداشت.

### پیشنهاد برای تست

بهتر است Backend یک مکانیزم برای ارسال **Mock/Fake Event** در محیط تست فراهم کند تا بتوان Eventهایی مانند `OnMarketPriceChanged` را به‌صورت دستی ارسال و رفتار Frontend را بررسی کرد.

این کار باعث می‌شود تست Real-time بدون نیاز به ایجاد شرایط واقعی بازار انجام شود و زمان زیادی برای تست دستی صرف نشود.
