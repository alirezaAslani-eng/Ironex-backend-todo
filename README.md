

## عدم عملکرد ایونت تغییر قیمت بازار
- ایونت `marketPriceChanged` در حال حاضر ارسال نمی‌شود یا عملکرد درستی ندارد. لطفاً بررسی شود که این ایونت در تمامی سناریوهای مورد انتظار منتشر شود.

## عدم به‌روزرسانی لحظه‌ای پس از انجام معامله
- اگر سفارش فروش با قیمت بالاتر یا سفارش خرید با قیمت پایین‌تر ثبت شود، به‌گونه‌ای که معامله به نفع معامله‌کننده انجام شود، سرور هیچ ایونتی برای به‌روزرسانی لحظه‌ای (Real-time) ارسال نمی‌کند.
- پس از رفرش صفحه، مشخص می‌شود که سفارش با موفقیت انجام شده است، اما تا قبل از رفرش هیچ تغییری در داده‌ها اعمال نمی‌شود.
- در حال حاضر تنها بخشی که به‌صورت لحظه‌ای به‌روزرسانی می‌شود order book  هست.
## 403 بعد از سوییچ حساب حقوقی
- بعد از سوییچ به یک حساب حقوقی، برخی APIها مانند **Dashboard** و **Wallet** با وضعیت **403 Forbidden** پاسخ می‌دهند. لطفاً بررسی کنید که بعد از سوییچ، سطح دسترسی یا توکن به‌درستی به‌روزرسانی می‌شود.

## ریسپانس `/auth/login-cookie`
- ریسپانس API `/auth/login-cookie` حتماً باید فیلد `hasPassword` را برگرداند؛ فرانت‌اند برای تصمیم‌گیری در فرآیند ورود به این مقدار نیاز دارد.

## ایجاد حساب حقوقی برای کاربر احرازنشده
- توانستم برای شماره **09936460918**، با وجود اینکه احراز هویت نشده است، حساب حقوقی ایجاد کنم. لطفاً بررسی کنید که آیا این رفتار مطابق منطق سیستم است یا یک باگ محسوب می‌شود.

## افزودن کارمند با شماره مالک شرکت
- برای شرکت **دایان داده پرداز**، شماره **09936460918** که مالک شرکت است را مجدداً به‌عنوان کارمند اضافه کردم و سیستم این عملیات را پذیرفت.
- **نکته:** این شماره احراز هویت نشده است. آیا علت این رفتار، احراز نبودن شماره است یا این مورد نیز یک باگ محسوب می‌شود؟

## احراز هویت
- به یک API نیاز داریم که برای هر سطح KYC، قابلیت‌ها و محدودیت‌های آن سطح را به‌صورت یکجا برگرداند.
- برای مثال:
  - امکان برداشت
  - سقف برداشت
  - سقف واریز
  - سایر قابلیت‌ها و محدودیت‌های مربوط به همان سطح
- این کار باعث می‌شود فرانت‌اند نیازی به هاردکد کردن قوانین نداشته باشد.

## به‌روزرسانی SignalR کیف پول
- بعد از شارژ کیف پول، Hub مربوط به `/hubs/wallet` اطلاعات کیف پول را به‌روزرسانی نمی‌کند و تغییرات به کلاینت ارسال نمی‌شود.

## رفتار API `/merge-account`
- پیشنهاد می‌شود API `/merge-account` پس از انجام موفق عملیات، توکن‌های فعلی کاربر را باطل یا حذف کند تا فرانت‌اند کاربر را به صفحه ورود هدایت کرده و مجدداً احراز هویت انجام شود.

## اند پوینت های مورد نیاز برای داده چارت ها
- در حال حاضر به دو API مجزا نیاز داریم:
  1. روند تغییرات قیمت یک محصول در بازه زمانی.
  2. روند تغییرات سود و زیان (P&L) یا ارزش دارایی کاربر در بازه زمانی.
- همچنین اگر API دوم یک فیلد مانند `isInProfit` یا `isInLoss` نیز برگرداند، سمت فرانت می‌توانیم ساختار ساده‌تر و بهینه‌تری برای نمایش وضعیت سود و زیان داشته باشیم.
