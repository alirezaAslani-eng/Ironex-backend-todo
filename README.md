### موارد بک اند

##### ای پی ای برای دریافت لیست ربات‌ها، فقط با پراپ‌های مورد نیاز و نه یک آبجکت بزرگ.
##### یک API جدا برای دریافت اطلاعات یک ربات؛ از آنجایی که اطلاعات یک ربات خیلی بزرگ است، برای لیست ربات‌ها به این حجم از اطلاعات نیاز نداریم.
##### یک API برای ایجاد ربات نیاز داریم.
##### یک API برای فعال و غیرفعال کردن یک ربات. این پارامتر می‌تواند در صفحه آپدیت کل ربات هم استفاده شود. از آنجایی که در هر ردیف جدول یک Toggle Button برای این اکشن داریم، این به معنی آپدیت کل ربات نیست و نیازی به فرستادن کل آبجکت ربات نداریم.

##### در حالت دمو سفارش ثبت می‌شود، در لیست سفارش‌های حالت دمو نمایش داده می‌شود و Order Book هم Response درستی می‌دهد؛ ولی کیف پول کاربر در حالت دمو هنگام معامله از موجودی کم نمی‌شود، حتی بعد از Refresh.

##### هنوز بعضی از قسمت‌های مهم هنگام ایجاد سفارش از نوع Limit با SignalR آپدیت نمی‌شوند، مثل لیست سفارش‌ها و کیف پول کاربر.

##### هنگام فروش یک دارایی و Fill شدن سفارش، کیف پول کاربر باید افزایش پیدا کند؛ ولی بعد از Fill شدن سفارش فروش، کیف پول آپدیت نمی‌شود، حتی بعد از Refresh.

##### در معامله ۱۰ درصد، به جای کم شدن ۱۰ درصد از کیف پول هنگام خرید، کل ۱۰۰ درصد کم می‌شود، حتی با وجود ارسال فیلد `"settlementMode": 1`.

##### ای پی ای `/api/v1/market/depth/REBAR` حتی با دریافت Query مربوط به `settlementMode=1`، بین سفارش‌های ۱۰ درصد و سفارش‌های معمولی تفکیک قائل نمی‌شود و همه سفارش‌ها را در Response برمی‌گرداند.

##### با اینکه اعتبار معاملاتی داشتم و `buyingPower` کافی بود، اجازه معامله داده نمی‌شد. ظاهراً Backend فقط موجودی کیف پول اصلی را در نظر می‌گیرد و اعتبار معاملاتی را محاسبه نمی‌کند.

##### بعد از خرید ۱۰۰۰ کیلو REBAR، سطح وفاداری کاربر تغییر نکرد و همچنان صفر درصد باقی ماند.

##### سویچ به حساب حقیقی با Endpoint `/api/v1/auth/switch-personal` Response موفق برمی‌گرداند، ولی کاربر به حساب حقیقی خودش برنمی‌گردد و حساب حقوقی قبلی هم همچنان `isActive: true` باقی می‌ماند.

##### هنگام انجام معامله، ایونت‌های `onTradeExecuted` و `marketPriceChanged` دیگر ارسال نمی‌شوند و در نتیجه آپدیت Real-time انجام نمی‌شود.

##### یک API برای دریافت لیست سطوح وفاداری کاربر نیاز داریم؛ این API نباید فقط برای Admin قابل دسترسی باشد.

##### بعد از Unsubscribe، ایونت‌ها و Listenerهای مربوط به آن باید به‌درستی Cancel و متوقف شوند.
