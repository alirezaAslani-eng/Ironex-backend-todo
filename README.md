آقا شاهین، یک مشکل دیگه هم مربوط به SignalR داریم.

وقتی من برای گرفتن Order Book به endpoint زیر request می‌زنم:

`/api/v1/market/depth/`

ممکنه همراه request یک Query/Parameter بفرستم که نوع داده را مشخص می‌کنه؛ مثلاً:

* `isDemo=true`
* یا حالت ۱۰٪
* یا هر پارامتر دیگه‌ای که باعث تغییر داده‌ی Order Book میشه.

خود API می‌تونه بر اساس این پارامترها response صحیح برگردونه، اما مشکل اینجاست که بلافاصله بعد از دریافت response، SignalR یک `OrderBookUpdated` ارسال می‌کنه و داده‌ی قبلی/متفاوتی رو روی response API overwrite می‌کنه. در نتیجه UI داده‌ی اشتباه نمایش میده.

راه‌حلی که به ذهن من رسیده اینه که هنگام fetch کردن `/api/v1/market/depth/`، تا زمانی که response این endpoint به کلاینت نرسیده، اجازه ندیم SignalR آپدیت Order Book رو اعمال کنه.

از سمت بک‌اند هم اگر امکانش هست، منطق ارسال `OrderBookUpdated` بر اساس Query/Parameter دریافتی از request تغییر کنه؛ یعنی مثلاً اگر request با `isDemo=true` ارسال شده، داده‌ای که SignalR برای `OrderBookUpdated` ارسال می‌کنه هم مربوط به همون حالت باشه.

در واقع هدف اینه که این دو جریان با هم تداخل نداشته باشن:

1. ابتدا `/api/v1/market/depth/` بر اساس پارامترهای request، Order Book صحیح رو برگردونه.
2. تا زمان دریافت response، SignalR باعث overwrite شدن داده نشه.
3. بعد از اون، `OrderBookUpdated` هم بر اساس همان context/پارامترهای مربوط به request، آپدیت صحیح رو ارسال کنه.

اگر از سمت بک‌اند راه بهتری برای حل این race condition بین API response و SignalR وجود داره، ممنون میشم همون روش رو پیاده کنیم.

### 6. تشخیص نوع معامله در `Place Order / Create Order`

در Feature مربوط به معاملات ۱۰ درصدی، زمانی که کاربر این نوع معامله را فعال می‌کند، برای ثبت سفارش از API زیر استفاده می‌کنم:

```text
POST /api/v1/orders
```

**سؤال:**

در Body درخواست باید چه فیلد یا مقداری ارسال کنم تا Backend متوجه شود این سفارش از نوع **معاملات ۱۰ درصدی** است؟

مثلاً آیا باید چیزی مشابه این ارسال شود:

```json
{
  "isThenPrecent": boolean
}
```

یا فیلد/مقدار دیگری برای مشخص کردن نوع معامله وجود دارد؟

لطفاً نام دقیق فیلد و مقادیر قابل قبول آن را مشخص کنید تا Contract مربوط به `CreateOrder / PlaceOrder` را درست پیاده‌سازی کنم.

سلام، چند مورد درباره Feature مربوط به **Margin / اعتبار معاملاتی** دارم که برای پیاده‌سازی فرانت نیاز به بررسی و مشخص شدنشان دارم.

### 1. باگ API — Margin Transfer In

**Endpoint:**
`POST /api/v1/wallet/margin/transfer-in`

در حال حاضر این API با خطای زیر مواجه می‌شود:

```text
System.InvalidOperationException:
The AuthorizationPolicy named: 'margin-trade' was not found.
```

لطفاً بررسی کنید مشکل از Authorization Policy یا تنظیمات دسترسی این Endpoint هست یا خیر.

---

### 2. مقدار اعتبار معاملاتی کاربر

در فایل/APIهایی که ارسال شده، جایی مشخص نشده که **مقدار اعتبار معاملاتی (Margin / Trading Credit) کاربر چقدر است.**

برای فرانت نیاز دارم بتوانم مقدار دقیق اعتبار کاربر را دریافت کنم تا بر اساس آن:

* میزان اعتبار معاملاتی کاربر را نمایش دهم.
* قدرت خرید کاربر را محاسبه و نمایش دهم.
* در صورت نیاز، حداکثر مبلغ قابل درخواست/استفاده را به کاربر نشان دهم.

**سؤال:**
آیا APIای برای دریافت مقدار `Trading Credit / Margin Credit` کاربر وجود دارد؟

اگر وجود دارد، لطفاً Endpoint و Response آن را مشخص کنید.

---

### 3. تسویه بدهی (Debt Settlement)

در توضیحات Feature این مورد را دیدم:

> «کاربر چند روز (مثلاً ۳ روز) فرصت دارد بقیه پول را واریز کند و دکمه "تسویه" را بزند تا جنس آزاد شود و به کیف پولش منتقل شود.»

گفته شده این endpoint نیاز هست :  `/api/v1/wallet/credit/contracts/{id}/settle`

**سؤالات:**

* آیا هر اکشنی که باعث بدهکار شدن کاربر میشود قرار داد اش میاد اینجا مثلا برای معاملات 10 درصد و اعتبار معاملاتی که کاملا از هم جدا هستن ولی در هر دو کاربر به ما بدهکار میشود.

---

### 4. دلیل Locked بودن دارایی‌ها

برای لیست دارایی‌های کاربر، نیاز دارم بدانم اگر یک Asset در وضعیت `Locked` قرار دارد، **دلیل Locked بودن آن چیست.**

در حال حاضر فقط داشتن چیزی مثل:

```text
lockedBalance
```

برای UI کافی نیست، چون از روی آن نمی‌توانم به کاربر توضیح بدهم چرا دارایی او قفل شده است.

مثلاً ممکن است دلیل Locked بودن یکی از این موارد باشد:

* بدهی مربوط به Margin
* در انتظار تکمیل معامله
* در حال تسویه
* سایر محدودیت‌های سیستمی

**سؤال:**
**آیا اسلا محصولات که کاربر تا بدهی را نپردازد قفل هستن وارد لیست assets میشوند ؟**

یا API مربوط به Assetها علاوه بر `lockedBalance`، دلیل یا نوع Lock را هم برمی‌گرداند؟

مثلاً چیزی در این ساختار:

```json
{
  "lockedBalance": 10000000,
  "lockReason": "MARGIN_DEBT"
}
```
